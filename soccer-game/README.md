# 블레이즈 일레븐 (Blaze Eleven)

필살기가 있는 11대11 아케이드 축구 토너먼트 게임입니다. 브라우저에서 바로 실행되며,
외부 이미지·사운드 파일 없이 캔버스와 WebAudio로 모든 그래픽과 효과음을 만듭니다.

## 게임 구성

- **토너먼트**: 12개국 중 한 팀을 골라 8강 → 4강 → 결승. 다른 경기는 전력 기반으로
  시뮬레이션되고, 진행 상황은 브라우저에 자동 저장됩니다(이어하기).
- **11대11 경기**: 방송 중계 시점의 원근 카메라, 포메이션 기반 팀 AI(압박·커버·대인
  마크·침투·지원 움직임), 골키퍼 다이빙, 스로인·코너킥·골킥·프리킥(수비벽)·페널티킥,
  파울과 옐로/레드카드, 골 리플레이, 하프타임, 무승부 시 승부차기.
- **세밀한 조작**: 파워 게이지 슛, 타이밍 피니시(킥 직전 재입력 시 PERFECT),
  감아차기·칩슛, 방향·거리 기반 패스 보조, 원터치 예약 입력, 방향별 개인기
  (헛다리·마르세유 룰렛·드래그백·레인보우 플릭·치고 달리기), 질주 시 공이 발에서
  멀어지는 드리블, 스태미나.
- **필살기**: 팀마다 고유한 필살 슛(화염·번개·회오리·유성·빙결·환영·용·백호).
  게이지가 100%가 되면 컷인 연출과 슬로모션, 속성별 궤적·파티클·화면 흔들림이 나오고,
  진로의 수비수는 튕겨 나가거나 얼어붙습니다. 수비 시에는 게이지 50%로 필살 태클.
  컷인 동안에는 카메라가 낮은 옆 각도로 내려가고, 필살 슛은 공 뒤에서 따라가며,
  골 리플레이는 골대 뒤에서 보여 줍니다.
- **필살 타이밍 대결**: 내 필살기 컷인 중 나오는 막대가 초록 구간에 왔을 때 슛 버튼을 누르면
  PERFECT(키퍼가 막기 훨씬 어려움). 상대 필살 슛이 날아올 때는 우리 키퍼 주위 고리가 초록이
  될 때 슛(막기) 버튼을 누르면 선방 확률이 크게 오릅니다. 필살기도 막을 수 있는 승부가 됩니다.
- **풋볼 매니저식 연출**: 경기 전 전술(포메이션·공수 성향·압박), 기자회견,
  라커룸 팀 토크(어조 + 발언), 에이스 1:1 면담, 하프타임 토크와 전술 변경,
  경기 중 터치라인 지시, 경기 후 토크. 선수마다 성격(열정적·침착함·예민함·자신만만·
  승부욕)이 있어 같은 말에도 반응이 다르며, 사기가 속도·정확도·게이지 충전에 반영됩니다.
  경기 후에는 선수 평점과 MOM이 나옵니다.

선수·감독 이름은 모두 가상의 인물입니다.

## 조작법

| 키 | 공격 | 수비 |
| --- | --- | --- |
| WASD / 방향키 | 이동 | 이동 |
| Shift | 질주 | 질주 |
| J | 패스 (길게 = 먼 동료) | 선수 전환 |
| K | 슛 (길게 = 파워, 킥 직전 다시 누르면 타이밍 피니시) | 스탠딩 태클 |
| L | 스루패스 | 슬라이딩 태클 |
| I | 로빙 패스 / 측면에서는 크로스 | 누르는 동안 동료 압박 |
| E + K / Q + K | 감아차기 / 칩슛 | |
| U (+ 방향) | 개인기 | |
| Space | 필살기 (게이지 100%) | 필살 태클 (게이지 50%) |
| Esc / P | 일시정지 · 터치라인 지시 | |

방향키 사용자는 Z(패스)·X(슛)·C(스루)·V(로빙)도 쓸 수 있습니다. 게임패드(표준 배치)는
경기와 메뉴(십자키 이동, A 선택, B 뒤로, Start 재개) 모두 지원합니다.

### 터치 (휴대폰·태블릿)

- **이동**: 화면 왼쪽 아무 곳이나 누른 채 끌면, 손가락 자리에 조이스틱이 생깁니다.
- **버튼**: 오른쪽 아래 작은 반투명 버튼. 상황에 따라 이름이 바뀝니다
  (공격: 슛·패스·스루·로빙/크로스·질주·개인기·필살 / 수비: 태클·전환·슬라이딩·압박·필살태클 /
  세트피스: 스로인·크로스·롱킥 등).
- **슛 제스처**: 길게 눌러 파워, 위로 밀며 떼면 칩슛, 옆으로 밀며 떼면 감아차기.
- 화면을 탭하면 골 장면·리플레이를 넘기고, 오른쪽 위 II 버튼으로 일시정지합니다.
- 휴대폰 화면에서는 점수판·게이지·중계 자막을 위쪽에 작게 모으고, 미니 레이더를 보여 줍니다.
- 설정의 '터치 버튼'에서 자동(마지막으로 쓴 입력 장치 기준)·항상 표시·끄기를 고를 수 있습니다.
- 골·필살기·슈퍼 세이브 때 짧게 진동합니다(지원하는 휴대폰, 설정에서 끌 수 있음).
- 필살기 컷인·추격 장면에서는 버튼·레이더·안내를 걷어 화면을 비웁니다(타이밍 대결 버튼만 남김).

## 실행

```bash
cd soccer-game
npm install
npm run dev       # 개발 서버
npm run build     # 타입 검사 + dist/ 빌드 + dist/blaze-eleven.html (단일 파일)
```

`dist/blaze-eleven.html`은 JS·CSS가 모두 인라인된 단일 파일이라 더블클릭으로 열거나
어디에든 올려서 바로 플레이할 수 있습니다(폰트만 Google Fonts에서 불러옴).

## 코드 구조

```
src/
  main.ts                 진입점
  app.ts                  화면 흐름 (타이틀·팀 선택·대진표·경기 전/하프타임/경기 후·우승)
  tournament.ts           대진표, 다른 경기 시뮬레이션, 저장
  data/
    teams.ts              12개국 데이터, 필살기, 선수 생성(시드 고정)
    formations.ts         포메이션 슬롯
    talks.ts              기자회견·팀 토크·성격 반응·중계 멘트
  game/
    match.ts              경기 상태 머신, 점유·골키퍼 판정, 세트피스, 골/리플레이, 시간
    ai.ts                 팀 AI (포지셔닝, 압박, 공 가진 선수의 판단, 골키퍼)
    control.ts            사람 조작 (드리블·킥 입력, 선수 전환, 세트피스 조준)
    actions.ts            패스·슛·개인기·태클·필살기 궤적
    shootout.ts           승부차기
    entities.ts           공 물리(스핀·바운드·골대·골망), 선수 이동
    renderer.ts           원근 카메라 렌더링, 선수 드로잉, 이펙트, HUD, 컷인
    camera.ts, particles.ts, audio.ts, input.ts, geo.ts, math.ts
  ui/                     DOM 헬퍼, 터치 컨트롤
```

난이도 아마추어·프로에서는 사람 쪽 태클 판정이 조금 넉넉하고, 공을 막 받은 순간에는 CPU가
바로 태클하지 않아 첫 터치할 여유가 있습니다.

밸런스 조정은 `game/match.ts`의 `DIFFS`(난이도별 CPU 파라미터)와
`data/teams.ts`의 팀 능력치에서 할 수 있습니다.

## 그래픽 방식: 2.5D 캔버스를 유지하는 이유

경기 세계는 이미 3차원 좌표(x·y·높이)로 시뮬레이션되고, 렌더러는 자유 원근 카메라로 이를
투영합니다. 선수만 2D로 그려 세워 두는 방식(빌보드)입니다. 그래서 카메라 각도를 바꾸는
연출(컷인 저각, 공 추적, 골대 뒤 리플레이)은 지금 구조에서도 가능하고, 실제로 넣었습니다.

재미·기술(성능)·그래픽 품질 세 관점에서 따로 검토했고, 셋 모두 '2.5D 유지 + 다듬기'로
같은 결론을 냈습니다. 실제로 Three.js 3D 시제품을 같은 장면에 맞춰 비교해 보니, 휴대폰에서
선수 키가 20~50px인 경기 화면에서는 차이가 거의 없었고 조명 때문에 유니폼 색이 어두워져
오히려 팀 구분이 어려웠습니다. 3D 전환은 파일이 3~4배 커지고 발열·배터리 부담과 회귀 위험이
크며, 사용자가 겪은 '버튼·글씨가 선수를 가린다' 문제는 화면 배치 문제라 3D로 바꿔도 남습니다.
재미의 핵심인 조작감·판정·필살 연출은 로직과 카메라 연출에서 나오므로 2.5D를 다듬었습니다.
